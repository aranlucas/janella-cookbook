## Why plan 001 was shipped

It is the highest-leverage user-facing correctness fix: every category entry
point (`/categories`, the home "Browse by course" index, and each recipe's
course/cuisine links) lands on results that do not match the category or the
count shown on the card, and sorting there only reorders one page. The fix
reuses the existing structured filters in `listRecipes`, needs no schema or
dependency change, and is fully verifiable by the repo's Vitest suite,
typecheck, lint and production build. Plan 003 is more valuable long-term but
is a design spike that changes an assistant-facing contract; plan 002 is
narrower (an API filter no first-party UI sends today).
