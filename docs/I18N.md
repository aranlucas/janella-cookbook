# Internationalization (i18n) Guide

This document explains how to use the internationalization features in the Janella Cookbook application.

## Overview

The app supports multiple languages through a combination of:

1. **next-intl** for UI text translations (labels, buttons, messages)
2. **Database-stored translations** for recipe content (titles, ingredients, instructions)
3. **Automated GitHub Actions** for translating recipes using AI

## Supported Languages

Currently supported locales:

- **en** - English (default)
- **es** - Spanish (Español)
- **fr** - French (Français)
- **de** - German (Deutsch)
- **it** - Italian (Italiano)
- **pt** - Portuguese (Português)
- **ja** - Japanese (日本語)
- **ko** - Korean (한국어)
- **zh** - Chinese (中文)

## Architecture

### Database Schema

The translation system uses these Prisma models:

```prisma
model Recipe {
  locale       String              @default("en")
  translations RecipeTranslation[]
  // ... other fields
}

model RecipeTranslation {
  recipeId    String
  locale      String
  title       String
  description String?
  servings    String?
  notes       String?
  ingredients  IngredientTranslation[]
  instructions InstructionTranslation[]
  @@unique([recipeId, locale])
}

model IngredientTranslation {
  originalIngredientId String
  name  String
  unit  String?
  notes String?
  group String?
}

model InstructionTranslation {
  originalInstructionId String
  text  String
  group String?
}
```

**Key Design Decisions:**

- Recipes store their **original language** in the `locale` field
- Translations are **stored separately** to avoid data duplication
- **Quantities stay the same** across languages (no unit conversion)
- Translations **reference original IDs** to maintain sort order
- **Cascade deletes** ensure translations are cleaned up when recipes are deleted

## Usage

### 1. Getting Localized Recipes

Use the helper functions in `lib/i18n-helpers.ts`:

```typescript
import {
  getLocalizedRecipe,
  getLocalizedRecipeBySlug,
} from "@/lib/i18n-helpers";

// Get a recipe by ID
const recipe = await getLocalizedRecipe("recipe-id", "es");

// Get a recipe by slug
const recipe = await getLocalizedRecipeBySlug("chocolate-cake", "fr");

// Get multiple recipes
const recipes = await getLocalizedRecipes({
  locale: "de",
  limit: 20,
  offset: 0,
  where: { cuisine: "Italian" },
});
```

**How it works:**

- If a translation exists for the requested locale, it returns the translated version
- If no translation exists, it falls back to the original recipe
- The `isTranslated` flag indicates whether the recipe is translated

### 2. Using UI Translations

For static text (buttons, labels, messages), use the `useTranslations` hook:

```typescript
import { useTranslations } from "next-intl";

function RecipeCard() {
  const t = useTranslations("recipe");

  return (
    <div>
      <h2>{t("ingredients")}</h2>
      <p>{t("prepTime")}: {prepTime} {t("time.minutes")}</p>
    </div>
  );
}
```

Translation messages are stored in `/messages/{locale}.json`.

### 3. Language Switcher

Add the `LanguageSwitcher` component to your UI:

```typescript
import { LanguageSwitcher } from "@/components/language-switcher";

function Header() {
  return (
    <header>
      <nav>
        {/* ... other nav items */}
        <LanguageSwitcher />
      </nav>
    </header>
  );
}
```

## Translation API

### POST /api/translate

Translate a recipe to a target language.

**Request:**

```json
{
  "recipeId": "clx123abc",
  "targetLocale": "es",
  "apiKey": "optional-api-key" // Falls back to OPENROUTER_API_KEY env var
}
```

**Response:**

```json
{
  "success": true,
  "data": {
    "translation": {
      "id": "clx456def",
      "recipeId": "clx123abc",
      "locale": "es",
      "title": "Pastel de Chocolate",
      "description": "Un delicioso pastel de chocolate...",
      "ingredients": [...],
      "instructions": [...]
    }
  }
}
```

**Error Responses:**

- `400` - Invalid request (missing fields, invalid locale format)
- `404` - Recipe not found
- `409` - Translation already exists (use PUT to update)
- `500` - Translation failed

### GET /api/translate

Get an existing translation.

**Query Parameters:**

- `recipeId` - Recipe ID
- `locale` - Target locale (e.g., "es", "fr")

**Example:**

```bash
curl "https://your-app.com/api/translate?recipeId=clx123abc&locale=es"
```

### PUT /api/translate

Update an existing translation (deletes old one and creates new).

**Request:** Same as POST

### DELETE /api/translate

Delete a translation.

**Query Parameters:**

- `recipeId` - Recipe ID
- `locale` - Locale to delete

## GitHub Actions

### Manual Translation

You can manually trigger recipe translations from GitHub Actions:

1. Go to **Actions** → **Translate Recipes** → **Run workflow**
2. Enter target locales (comma-separated): `es,fr,de`
3. Optionally specify recipe IDs to translate
4. Click **Run workflow**

The action will:

- Fetch all recipes (or specified ones)
- Translate them to each target locale
- Skip recipes that are already translated
- Provide a summary of successes/failures

### Automated Translation

The workflow runs automatically **every Sunday at 2 AM UTC** to translate any new recipes.

### Configuration

Set these GitHub Secrets:

- `OPENROUTER_API_KEY` - API key for OpenRouter (Claude 3.5 Sonnet)
- `PRODUCTION_URL` - Your production app URL (defaults to Railway app)

To translate existing recipes:

1. Run the GitHub Action (see above)
2. Or use the API directly:

```bash
curl -X POST https://your-app.com/api/translate \
  -H "Content-Type: application/json" \
  -d '{"recipeId": "your-recipe-id", "targetLocale": "es"}'
```

## Best Practices

### 1. Recipe Content

- **DO** translate ingredient names (e.g., "flour" → "harina")
- **DO** translate instructions
- **DO** translate descriptions and notes
- **DON'T** convert units (keep "2 cups" not "473 ml")
- **DON'T** translate quantities

### 2. UI Text

- Add new UI strings to `/messages/en.json`
- Organize by namespace (e.g., `common`, `recipe`, `forms`)
- Use nested keys for related content
- Keep keys in English for consistency

### 3. Translation Quality

The system uses **Claude 3.5 Sonnet** via OpenRouter for translations:

- High-quality, context-aware translations
- Maintains cooking terminology accuracy
- Preserves measurements and technical details
- Respects cultural cooking differences

### 4. Performance

- Translations are stored once and reused (no repeated API calls)
- Localized recipes fallback to original if translation missing
- Database indexes on `locale` and `recipeId_locale` for fast lookups

## Troubleshooting

### Translation fails with 500 error

Check:

- `OPENROUTER_API_KEY` is set correctly
- API key has sufficient credits
- Recipe exists in database
- Locale format is valid (ISO 639-1: "es", "fr", etc.)

### Language switcher doesn't work

Verify:

- Middleware is configured correctly (`middleware.ts`)
- Locale is included in `i18n.ts` locales array
- Messages file exists: `/messages/{locale}.json`

### Recipe not translated

Check:

- Translation exists: `GET /api/translate?recipeId=xxx&locale=es`
- Use `hasTranslation()` helper to verify
- Check GitHub Actions logs for translation errors
